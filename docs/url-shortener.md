## Running the Service

```powershell
cd generated/url_shortener
python -m uvicorn app.main:app --reload
```

The service listens on `http://localhost:8000`. Interactive docs are
available at `http://localhost:8000/docs` (auto-generated by FastAPI from
the same route definitions validated against `artifacts/openapi.yaml`).

The SQLite database file is created automatically at
`generated/url_shortener/data/url_shortener.db` on first run.

## API Reference

Full machine-readable contract: [`artifacts/openapi.yaml`](../artifacts/openapi.yaml).

### `POST /urls` — Create a short URL

**Request**
```json
{ "url": "https://example.com/some/very/long/path" }
```

**Response — 201 Created** (new mapping)
```json
{ "short_code": "abc123x", "short_url": "/abc123x" }
```

**Response — 200 OK** (an active mapping for this `url` already exists;
the existing code is returned instead of creating a duplicate — see
architecture.md §12 for rationale)
```json
{ "short_code": "abc123x", "short_url": "/abc123x" }
```

**Response — 422 Unprocessable Entity** (malformed / non-http(s) URL)
```json
{ "detail": [ { "msg": "..." } ] }
```

### `GET /{short_code}` — Redirect

- **302 Found** → redirects to the original URL, and durably records the
  redirect (increments `redirect_count`, updates `last_accessed_at`,
  appends a `redirect_events` row).
- **404 Not Found** → unknown short code.
- **410 Gone** → short code exists but its `expires_at` has passed.

### `GET /urls/{short_code}/analytics` — Analytics

**Response — 200 OK**
```json
{
  "short_code": "abc123x",
  "original_url": "https://example.com/some/very/long/path",
  "created_at": "2026-09-22T18:00:00+00:00",
  "redirect_count": 3,
  "last_accessed_at": "2026-09-22T18:05:00+00:00"
}
```

**Response — 404 Not Found** → unknown short code.

### `GET /analytics/dashboard` — Aggregate Dashboard Summary (read-only)

Composes existing `urls` + `redirect_events` data into totals, a top-N
ranking, a clicks-over-time series, and recent events. Introduces no new
storage, no new analytics engine — powers the static dashboard UI at
`GET /dashboard/` (see "Analytics Dashboard (UI)" below).

**Query params (all optional):** `top` (default 5), `recent` (default
10), `days` (default 7)

**Response — 200 OK**
```json
{
  "total_urls": 2,
  "total_redirects": 3,
  "top_urls": [
    {"short_code": "GrW4Itv", "original_url": "https://example.com/a", "redirect_count": 2, "last_accessed_at": "2026-09-23T09:00:27+00:00"}
  ],
  "clicks_over_time": [{"date": "2026-09-23", "count": 3}],
  "recent_events": [
    {"short_code": "GrW4Itv", "original_url": "https://example.com/a", "accessed_at": "2026-09-23T09:00:27+00:00"}
  ]
}
```

## Analytics Dashboard (UI)

Open **`http://localhost:8000/dashboard/`** after starting the service.
A single static HTML/CSS/JS page (no build step, no new framework,
same dark-theme styling as `docs/user-guide.html`) that calls only
`GET /analytics/dashboard` and renders: total URLs created, total
redirects/clicks, top accessed short URLs, a clicks-over-time bar
chart, and recent analytics events — with loading, empty-data, and
API-error states all handled client-side. Modular by design: new
analytics cards can be added by writing one render function and
registering it in the `WIDGETS` array in
`generated/url_shortener/app/static/dashboard/index.html`.

## Code Structure

```

  app/

    api/urls.py                      # POST /urls, GET /urls/{code}/analytics

    models/url.py                    # Pydantic request/response + UrlRecord

    models/exceptions.py             # ShortCodeNotFoundError, ShortCodeExpiredError

    db.py                            # SQLite connection + schema bootstrap

    test_url_service.py              # unit tests (service layer)

    test_dashboard_api.py            # dashboard API + static UI integration tests
```

## Persistence

Schema: [`artifacts/schema.sql`](../artifacts/schema.sql) — `urls` table
(one row per short code) + `redirect_events` table (one row per redirect,
enabling future trend analytics without a schema migration). The
dashboard reads from these same two tables only — no new tables.

## Known Limitations (honest, not hidden)

- No authentication/authorization (ASM-002) — anyone can create or view
  analytics for any short code.
- No rate limiting.
- Single-node SQLite persistence — see architecture.md §7 for the
  documented (not implemented) evolution path to Redis + PostgreSQL +
  horizontal scaling.
- Analytics are aggregate count + per-event timestamp only; no IP/user
  agent capture (ASM-004), by deliberate design choice to minimize
  unnecessary data collection in a prototype.
