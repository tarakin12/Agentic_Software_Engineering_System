Agentic Software Engineering System

A user's guide to running a genuine agentic software-engineering workflow — from natural-language requirement to reviewable engineering outcome — using GitHub Copilot Agent mode.

No external LLM API No API key required Python 3.11+ GitHub Copilot Agent Mode FastAPI + SQLite prototype

Key Features

🧭

Single Entry Point

You only ever talk to the Engineering Orchestrator — it delegates to 7 specialized agent roles internally.

❓

Ambiguity Detection

Material ambiguity halts the workflow and asks clarifying questions instead of guessing.

🗂️

Artifact-Driven Handoff

Every stage persists real files (.agentic/) — no reliance on chat memory alone.

🔀

Dependency-Aware Task Graph

Independent tasks are identified and can run in parallel; blocked tasks wait correctly.

🏚️

Brownfield Reasoning

Inspects existing repositories before proposing any change — never assumes impact.

✅

Independent Validation

A separate Validation Engineer role cross-checks everything with mechanical evidence, not opinion.

♻️

Bounded Recovery

Failures trigger scoped rework (max 2 retries) — never silent infinite loops.

🖐️

Human Approval Gate

approval.json is never auto-set to APPROVED — a human must explicitly approve.

🔗

Full Traceability

Requirement → Acceptance Criterion → Task → Artifact → Test → Validation, all linked.

📊

Analytics Dashboard

A read-only dashboard UI composes the existing analytics data (totals, top URLs, clicks over time, recent events) — no new database or analytics engine.

Installation

  1. Clone the repository and open it in VS Code.
  2. Install Python dependencies: 
    pip install -r requirements.txt
  3. (Optional) Confirm everything currently in the repo already works: 
    python .agentic/tools/run_tests.py # expect 82 passed, 0 failed

Enabling GitHub Copilot Agent Mode

  1. Open the Copilot panel in VS Code.
  2. Select Agent mode (not plain Chat / Ask mode).
  3. Choose Claude Sonnet or another capable model from the model picker.
  4. Confirm the workspace is this repository — the orchestrator reads .github/copilot-instructions.md and .github/agents/*.agent.md automatically as repository-level instructions.

Running the Mandatory Scenario (URL Shortener)

This has already been executed and approved in this repository, but here is exactly how to (re)run it yourself:

  1. In Copilot Agent mode chat, type:
    "Use the Engineering Orchestrator to process this requirement: Build a scalable URL shortener service with APIs, persistence and analytics."
  2. The orchestrator inspects the repo, determines this is greenfield, and begins Requirement Analysis.
  3. Watch for ambiguity handling — five ambiguities exist (scale target, auth, expiration, analytics depth, duplicates) but are judged non-material, so the workflow proceeds with clearly labeled assumptions rather than halting.
  4. Progress is reported stage by stage (see Orchestration Stages below).
  5. When it reaches Human Approval, review .agentic/validation/validation-report.md and artifacts/engineering-summary.md, then respond with your decision (approve or request rework).
You do not need to manually invoke the Requirement Analyst, Architecture Designer, etc. — the orchestrator delegates to them internally and only surfaces what you need to review or approve.

Running the Generated URL Shortener App

cd generated/url_shortener
python -m uvicorn app.main:app --reload

Then open http://127.0.0.1:8000/ (landing info), /docs (interactive API docs), /dashboard/ (analytics dashboard UI), and try:

# Create a short URL
curl -X POST http://127.0.0.1:8000/urls -H "Content-Type: application/json" -d "{\"url\": \"https://example.com\"}"

# Redirect (use the short_code from the response above)
curl -i http://127.0.0.1:8000/<short_code>

# Analytics for one short code
curl http://127.0.0.1:8000/urls/<short_code>/analytics

# Aggregate analytics dashboard summary (new)
curl http://127.0.0.1:8000/analytics/dashboard

Orchestration Stages You'll See

[1/7] Requirement Analysis → normalized-requirement.json [2/7] Architecture → architecture.md (validated before proceeding) [3/7] Task Planning → tasks.json (dependency graph) [4/7] Engineering Implementation → generated/ (parallel tasks where possible) [5/7] Testing → real pytest execution, evidence saved [6/7] Validation → validation-report.md (independent review) [7/7] Human Approval → approval.json (PENDING until you decide)

If validation fails, expect: root cause → scoped rework task → re-execute only the affected task and its dependents → re-validate, capped at 2 automatic retries before requesting human review.

Approval Gates — When You'll Be Asked to Decide

  • Material requirement ambiguity (business objective, users, compliance undefined)
  • A high-risk architectural decision
  • Any potentially destructive repository change
  • Automatic recovery exceeding 2 retries
  • Final engineering approval, always
You will not be asked to approve every trivial step — only these controlled-autonomy checkpoints.

Troubleshooting

"Not Found" at http://127.0.0.1:8000/

Fixed — a landing route now returns service info at the root path. If you still see this, confirm you're running the latest generated/url_shortener/app/main.py and restart uvicorn.

pytest not found

Run pip install -r requirements.txt first.

Tests fail when run together but pass individually

This was a real issue we hit and fixed: two projects used a module named app, causing a Python import cache collision. Already resolved via unique importlib loading in the brownfield tests — should not recur.

FAQ

Does this call OpenAI/Anthropic/Azure OpenAI APIs?

No. GitHub Copilot Agent mode itself is the reasoning engine. All Python tools in .agentic/tools/ are dependency-free, deterministic bookkeeping — no network calls, no LLM SDKs.

Do I need an API key?

No — GitHub Copilot handles model access; this repository requires none of its own.

Is the URL shortener hardcoded into the orchestrator?

No. The agent definitions contain no URL-shortener-specific logic (verified: zero occurrences of "url"/"short_code" in .agentic/tools/*.py). It is the mandatory demonstration scenario, not a special case.

What if I disagree with the validation result?

You control the approval gate. Respond with a rework request instead of approving, and the orchestrator will create a scoped rework task rather than restarting everything.

Does the analytics dashboard change the existing API contract?

No. It adds one new, additive, read-only endpoint (GET /analytics/dashboard) that composes data already produced by the existing urls and redirect_events tables. POST /urls, GET /{short_code}, and GET /urls/{short_code}/analytics are unchanged — verified mechanically with validate_artifacts.py openapi (0 mismatches).

Does the dashboard use a new database or charting library?

No. It reads from the same SQLite tables (urls, redirect_events) via the existing repository layer, and the UI is a single static HTML/CSS/JS file with a small CSS-only bar chart — no new dependency, no build step.
